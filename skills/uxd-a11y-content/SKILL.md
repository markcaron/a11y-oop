# Review accessible content
## Work

Select applicable STR, TXT, IMG, MED, FRM, TAB and LOC records. Identify purpose and context before writing alternatives; distinguish decorative, functional and complex visuals. Assess meaningful equivalence, not mere attribute presence.

Review heading relationships, page/embed titles, understandable link/action text, visible labels/instructions, recovery messages and status intent. For tables, define useful headers, units and relationships with design and engineering. For media, determine modality, prerecorded/live state and applicable captions/transcripts/descriptions.

Include accessible-only strings in localization. Preserve existing approved prose and tone where possible. Separate suggestions about plain language or brand from substantiated standard failures. Do not invent the meaning of an unfamiliar chart or image.

## Handoff

Return targeted edits or findings in the requested scope, plus content intent that implementation must preserve. Association, focus and announcement behavior remain separate runtime checks.

## Shared context

Read [the contract](../shared/contract.md) for scoped inputs, result states and evidence requirements. Select only applicable rule IDs from [the shared catalog](../shared/catalog.json), using role, task, lifecycle stage and actual target. Related WCAG IDs require applicability/exception review; policy and APG guidance are not automatically WCAG failures.

Use [provider selection](../shared/providers.md) when a design-system component is involved. Framework and provider are independent; support mixed React/Web Component pages. Prefer installed documentation and versioned sources. Missing capability or evidence is Not tested, never a pass.
